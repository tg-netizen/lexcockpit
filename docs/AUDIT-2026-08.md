# LexCockpit — Audit, 9 August 2026

12,183 lines of Swift across 32 files, 55 self-tests, v0.25.0 running on
the author's Mac. Audited the way the website was: measure first, judge
after.

**Overall: 6.5 / 10.** Better engineered than the website it edits, and
undone by the same disease — the app cannot tell silence from failure.

---

## What is genuinely good

Not politeness. These are measured and they are unusual.

- **No crash surface.** Zero force-unwraps, zero `try!`, zero
  `fatalError`, one `as!`. For 12k lines of Swift touching the network,
  the filesystem and the Keychain, that is real discipline.
- **The lossy decoder.** 62 of the 166 `try?` are in `Models.swift`, and
  they are the `AnyJSON`/`LossyArray` pattern — a feed that ships one
  malformed row loses that row, not the section. That is deliberate and
  correct.
- **The Keychain memo.** Each item is read at most once per launch.
  Without it the app would prompt on every access.
- **Editorial safety in the editor.** Frontmatter round-trips
  byte-identically, saves carry the load-time SHA and surface 409/422 as
  a conflict rather than overwriting. `BlockVault` restores raw HTML
  blocks verbatim. These are the hard parts and they are done.

## P0 — the app cannot distinguish three states

`Workspace.swift` presents *never fetched*, *fetched and genuinely
empty*, and *fetched but the server returned nothing* identically:

```
Waiting list is empty
Trigger the free ingest scan — relevant RSS hits land here with a score.
```

`reviewQueueError` only catches a **thrown** error. It does not catch the
case that actually happened on 9 August: Supabase answered **HTTP 200
with `[]`** because the anon RLS policies were missing. Thirty-four items
were queued. The app told its user to run a scan they had already run.

The same shape appears on first launch: before any fetch, the array is
empty, so the app asserts the waiting list is empty before it has asked.

**This is the website's feed-health bug wearing a different hat.** There,
a ledger of nulls sat under a headline promising a refresh cadence. Here,
an empty array sits under a sentence asserting there is nothing to
review. In both cases the system reports success it has not earned.

**Fix:** a three-state model — `.never`, `.loaded(at: Date, count: Int)`,
`.failed(String)` — and a fourth signal worth having: *loaded, empty, but
the last ingest run reported items queued*. That contradiction is
detectable (`pipeline_runs.items_queued` vs what the queue returns) and
it is exactly the alarm that would have fired today.

## P1 — findings

| # | Finding | Evidence |
| --- | --- | --- |
| 1 | **Four subsystems have no tests at all** — Supabase, the updater, the Keychain, the offline queue | 55 tests cover frontmatter, slugs, blocks, date buckets. Every bug found on 9 Aug was in the untested four. |
| 2 | **Nine network calls do not reach the diagnostics ring** | 18 `URLSession.shared` calls, 11 `diagRecord`. Analytics (2), Onboarding (3), Radar (2), UpdateCheck (2) are silent. When a user says "it does not work", those four leave no trace. |
| 3 | **38 caches and state files decode with `try? … ?? []`** | A corrupt `bookmarks.json` makes projects vanish silently; a corrupt `state.json` resets the session without a word. v0.13.0 already shipped a fix for exactly this class (a legacy `projects.json` falling through to the bundle). |
| 4 | **The Keychain still prompts once per rebuild** | Known and documented. The self-signed identity does not carry ACL trust across binaries. Only a real Developer ID closes it. |
| 5 | **`ContentEditor.swift` is 2,636 lines** | The editor, the cache, the save path, the block palette and the Canva bridge in one file. Nothing is broken; everything is harder to test than it needs to be. |

## Update ideas, in the order I would build them

### 1 · Honest states everywhere (small, highest value)
The three-state model above, applied to every panel that fetches:
waiting list, radar, deploys, feeds. A panel that has never loaded says
so. A panel that loaded ten minutes ago says when. This is perhaps 150
lines and it removes a whole class of wrong advice.

### 2 · A self-test for the four untested subsystems
`--selftest` already exists and runs headless. Add: the Supabase URL
builder and its column list, `isNewer()` version comparison, the
updater's rollback path against a fake bundle, the queue's conflict
flag. All four are pure logic and need no network.

### 3 · "What changed since Thursday"
The website has `tracker-changelog.json` wired and empty; the app has a
radar section that already consumes it. Two ends of a product with
nothing in the middle. Whoever fills it — a weekly snapshot diff — makes
both halves work at once. This is the single feature with the best ratio
of value to effort in either repo.

### 4 · Promote a queue item to a draft, in one click
Today the waiting list is read-only: you see 34 items and then leave the
app to write. The obvious move is a button that opens the article
template pre-filled with the item's title, source URL and retrieval date
— and nothing else. Not a generated draft. The raw material, positioned.
This is the workflow the author actually described wanting.

### 5 · Diagnostics on every call, and a share button
Nine silent calls become eleven-of-eleven. Then one button that copies
the ring buffer with tokens redacted. Debugging by description is what
made today's Supabase problem take an hour.

### 6 · Signature pinning in the updater
The updater now verifies that the downloaded bundle's signature is
intact. It cannot verify *who* signed it, because an ad-hoc signature
carries no identity. With a real Developer ID that becomes a team-ID
requirement — and the same certificate ends the Keychain prompts. One
purchase closes two findings.

### 7 · Split `ContentEditor.swift`
Not urgent, and worth doing before the next large editor feature rather
than during it.

## What was not audited

- No UI automation pass. The panels were read as source, not driven.
- Canva OAuth was not exercised end to end.
- No performance measurement on a large content set.
- The website's tool logic (compliance thresholds, sector lists) is a
  separate open item and is tracked in that repository.
